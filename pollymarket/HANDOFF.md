# pollymarket — 交接紀錄

給人看的摘要,記錄這個專案目前進度到哪、討論過什麼、還有哪些事沒解決。下次不管是你自己回來看,還是開新的 Claude session 接手,先讀這份就能接上。

## 這個專案在幹嘛

觀察 Polymarket(預測市場平台)上「多結果互斥」(neg-risk)市場,看買齊所有結果的 Yes 份額總價是否低於 $1 —— 如果低於,理論上是無風險套利空間。

**這是純觀察工具,不是交易機器人。不碰錢包、不下單、不需要任何私鑰或 API key。** 目的是先用真實數據回答「網路上說的套利到底多常出現、多大、消失多快」,而不是憑感覺就丟真錢進去。

這個方向是討論後決定的:使用者一開始想「抓個賺錢模型直接拿錢給 Claude 操作」,但這風險很高(Claude 沒有資金託管能力、網路上的「穩賺模型」多半是倖存者偏差或詐騙、預測市場套利多半轉瞬即逝且規模小),所以先退一步做資料驗證。

## 目前狀態

- 程式碼已經寫好、測試過,實際跑過一輪真的抓到一筆案例(俄羅斯國會選舉市場,1.7% 價差,但可成交量只有約 20 股,規模小到不太有意義 —— 這正好印證了「機會存在但通常不值得追」的預期)
- 檔案位置:目前放在 `biangyang/Arduino` 這個 GitHub 倉庫底下的 `pollymarket/` 資料夾(分支 `claude/pollymarket-project-discussion-9mxqs8`),**已經 commit 並 push 上去了**
- 這個放置位置不理想:`Arduino` 倉庫本來是 Arduino IDE 官方原始碼的 fork,跟 pollymarket 完全無關,只是因為這次對話一開始系統把 session 綁定到這個倉庫,才先放這裡

## 檔案清單

- `scan_arbitrage.py` — 主程式,持續掃描、把每次結果(不管有沒有機會)記到 `data/observations.csv`
- `report.py` — 讀取 CSV,統計出現頻率、價差大小、機會持續多久
- `README.md` — 完整使用說明(怎麼裝、怎麼跑、參數意義)
- `requirements.txt` — 只需要 `requests` 套件
- `data/` — 已加入 `.gitignore`,不會被 commit(是本地產生的觀察紀錄)

## 討論中釐清的重要背景(使用者原本不清楚的部分)

- 使用者一開始不知道自己的 GitHub 帳號(`biangyang`)底下已經有 `Arduino` 這個倉庫,也不記得有把 GitHub 連動到 Claude
- 使用者原本以為現在這個對話跟以前寫網站時一樣是「直接動到自己電腦本地」—— 實際上這是 Claude 桌面 App 的「Code」功能,背後是雲端臨時容器,不是本機電腦。從截圖確認側邊欄的 `Arduino`、`stock coding`、`YHB_claude-agent` 都是各自獨立的 GitHub 倉庫分組,每個底下掛好幾個 session —— 代表**之前寫網站應該也是用同一套雲端機制**,只是連到別的倉庫,不是使用者以為的「本地終端機模式」
- 想在自己電腦上直接執行這個程式,需要:GitHub 存好 → 自己電腦 `git clone` 下來 → 本地安裝 Python 依賴 → 執行

## 還沒解決 / 待決定的事

1. **要不要搬到獨立的新 GitHub 倉庫?** 之前嘗試用工具直接建立 `pollymarket` 新倉庫,失敗了 —— 目前的 GitHub 整合權限只開放到 `Arduino` 這個倉庫,沒有「建立新倉庫」的權限。使用者需要自己手動在 github.com 建立一個空倉庫(右上角 `+` → `New repository`),建好後跟 Claude 說一聲,才能把程式碼搬過去
2. **要不要在自己電腦上跑?** 如果要,需要確認電腦上有沒有裝 Python,以及要不要裝終端機版的 Claude Code CLI 方便之後繼續改程式
3. **要不要排程長期收集資料?** 目前只手動跑過 `--once` 測試一次,還沒有真正跑一段時間累積數據來看 `report.py` 的完整統計結果

## 建議的下一步(照優先順序)

1. 使用者手動在 GitHub 建一個新的空倉庫(例如 `pollymarket`),或決定乾脆留在 Arduino 倉庫裡也行
2. 讓 `scan_arbitrage.py` 實際跑個一兩天收集數據(雲端 session 或本地都可以)
3. 跑 `report.py` 看實際數據,再決定這個方向值不值得往下做(例如要不要真的考慮小額實測)
